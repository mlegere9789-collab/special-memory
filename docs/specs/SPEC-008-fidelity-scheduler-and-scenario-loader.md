# SPEC-008: fidelity scheduler, sector streaming and scenario loader

Crate: `crates/battle-rules` (new modules `fidelity`, `aggregate`, `f1`, `sector`, `scenario`, `battle`), plus `hd-sim resolve` and `hd-sim fit-f1` in `shells/sim-cli`. The loader lives in `battle-rules` because only that crate may use `toml` and `serde` (ADR 0004). Conventions, units, provenance and source key follow SPEC-004 sections 1 and 2 and SPEC-005. Calibration targets here are **CT-80 to CT-88** (SPEC-004 and SPEC-005 already use CT-1 to CT-9). Test prefix **T8-**.

## 1. Purpose and definitions
Run a battlefield of about 100 km2 with up to about 165,000 soldiers engaged over three days (about 93,921 Union and 71,699 Confederate, contested, CWV p079, untagged; Plan 2.3), tens of thousands acting at once (Pickett's assault about 12,500 men in 9 brigades after 150 to 170 guns, CWV p069 tag P, p083), inside the 50 ms tick. Out of scope: morale, command latency, rendering.
- **Scenario class `fc`** (0, 1, 2): the finest class the scenario permits (ADR 0002). It is a scenario field, is written to the replay header `fidelity_class`, and is never read from hardware, thread count, frame rate or time.
- **Regiment** (SPEC-004) persists in every class and keeps orders and drill state. It is **agent-backed** (F0, F1: soldiers in the `AgentStore`) or **aggregate** (F2: no agents, one `Aggregate`).
- **Present**: arrived and not departed. **Reach**: max of `|u|`, `|v|` over `slot_layout(formation, fit)`, whole mm. **Gap** of r: mm between anchors of r and the nearest present enemy, less both reaches. `isqrt`: floor square root on `u128`. **Sector**: square map tile of `sector_mm`.

## 2. Data
**2.1 `data/rules/fidelity.toml`** (`fidelity.schema.json`, provenance rows, placeholders). Globals: `assign_interval_ticks 20`, `hysteresis_mm 50000`, `min_dwell_ticks 200`, `bundle_ticks 20`, `f2_interval_ticks 100`, `sector_mm 500000`, `hot_margin_sectors 1`, `grid_cell_mm 4000`, `max_grid_cells 4194304` (CT-85). `[[arm]] id (infantry|cavalry|battery), f0_mm, f1_mm`: infantry and cavalry 450000 / 1800000, battery 1200000 / 2400000. Basis: rifled musket effective 300 yd, extended about half a mile, shot maximum 1680 yd, canister effective 350 yd (CWV p459, V S21, V S19); F0 covers effective fire plus margin, F1 extended fire plus margin (CT-80).

**2.2 `data/rules/f1.toml`** (`f1.schema.json`), written only by `hd-sim fit-f1` from `qc/calibration/f0-curves.json` (CT-81; `confidence unverified`, note "fitted"): `[[hit]] weapon, bin, hits_per_shot_ppm` (bin = range / 25 m as in the range table; mean hits on a two-rank standing line in open ground, pierce included, cover excluded); `[[density]] formation, pm`; `[[rank_share]] ranks, rank, pm` (sums 1000); `[[region]] posture, legs_pm, torso_pm, head_pm` (sums 1000).

**2.3 Scenario `data/scenarios/<id>.toml`** (`scenario.schema.json`, `schema = "scenario/1"`). Integers only; no floats, string arrays or nested array tables; unknown keys refused. Times are whole seconds from scenario start (`tick = s * tick_hz`), lengths mm. Every `[[row]]` carries provenance.
- Top level: `id`, `title`, `date` (string), `clock_start_s`, `duration_s`, `tick_hz` (20), `fidelity_class`, `f0_cap` (soldiers allowed in F0), `agent_cap` (F0 plus F1; `f0_cap <= agent_cap <= 200000`). Caps are scenario data inside the scenario hash, never machine dependent (default 15000 / 35000, CT-82).
- `[map]` `width_mm, height_mm` (1..12000000), `origin_x_mm, origin_y_mm`. `[terrain]` as SPEC-004 section 5, or `source = "terrain/<name>.rows"` plus `source_hash` (hex string, FNV-1a 64): the same rows, one string per line, so a 1250 x 1250 grid stays out of the TOML.
- `[[unit]]` `id` (`[a-z0-9_-]{1,32}`), `side`, `parent` (`""` or unit id), `arm` (`infantry|cavalry|battery|hq`), `men`, `guns`, `training`, `weapon`, `rounds_per_man`, `commander` (`""` or a `data/history/commanders` id). `hq` units (`men = 0`) form the hierarchy and become no entity. A battery has `guns >= 1` and becomes a regiment of that many `F_GUN` agents; its `men` (crew) count only in strength checks.
- `[[arrival]]` `unit, at_s, x_mm, y_mm, heading_deg, formation, low_s, high_s` (evidence window containing `at_s`). `[[departure]]` `unit, at_s`.
- `[[strength_check]]` `at_s, side, men, tol_men`: sum of `men` of present units (the audit "strengths sum"). `[[objective]]` `id, side, x_mm, y_mm, radius_mm, points`; holder = side with strictly more fit soldiers inside the radius, else none.
- `[[trigger]]` `id, at_s, kind (order|fire_mode|resupply|marker), unit`, then per kind: order: `order (hold|move|form|face)` with `x_mm, y_mm, gait, formation, heading_deg` as SPEC-004; fire_mode: `target`; resupply: `rounds`. These are the fixed historical triggers, with their evidence window.
- `[[weather]]` `from_s, wind_x_mm_s, wind_y_mm_s, wet_pm, ground_pm, visibility_m`; first row `from_s = 0`; the last row with `from_s <= t` applies.

Fixture `data/scenarios/fid-small.toml` includes unit `buford_div` (Union cavalry, `men = 2700`, `confidence = "partial"`, source CWV p080 untagged, "about 2,700 troopers").

## 3. Loader and validation
`Scenario::from_toml_str(&str, &Tables, terrain_rows: Option<&str>) -> Result<Scenario, ScenarioError>`. Units are sorted by `id` bytewise, then `RegimentId` ascends over non-`hq` units, so file order never matters. Variants: `Data(DataError)`, `Reference`, `Duplicate`, `Range`, `Time`, `Cycle`, `Strength`, `Class`, `Terrain`, `Cap`. Rules: V1 float, unknown key, provenance; V2 duplicate ids; V3 every reference resolves; V4 `parent` chain acyclic, same side; V5 at most one arrival and departure per unit, every non-`hq` unit arrives, `0 <= at_s <= duration_s`, departure after arrival, `low_s <= at_s <= high_s`; V6 positions inside the map on non-blocking cells; V7 strength checks; V8 `fidelity_class <= 2`, `f0_cap <= agent_cap`; V9 `tick_hz` 20; V10 terrain hash; V11 at most 4096 units, 1,000,000 `men` per unit, no allocation from an unchecked count; V12 `verified` needs `second_source`. `scenario_hash(&Scenario) -> u64` is FNV-1a 64 over a canonical little-endian encoding of the parsed, sorted value (whitespace and row order do not matter). `tools/validate_data.py` checks the same files against the schema.

## 4. The scheduler
`Battle { state: BattleState, fid: FidelityState, scenario: Scenario }`. `Battle::step` is SPEC-005 section 7 plus: on a **boundary** (`tick % assign_interval_ticks == 0`), before movement: (a) departures, arrivals, triggers, weather for this tick, ascending `(at_s, id)`; (b) classification; (c) hand-overs, ascending regiment id; (d) sector update (section 7). Then movement, F0/F1 fire, flight and hit, F1 bundle and delay-ring release, F2 exchange, casualties, decay. Nothing reads anything but state.

**4.1 Classification** (pure integer function of state). For each present regiment r, ascending id: `gap_r = min over present enemies e of max(0, isqrt(dx^2 + dy^2) - reach_r - reach_e)` (i128 mm, all pairs, ascending ids). `geo_r = 0` if `gap_r <= f0_mm(arm) + (hysteresis_mm if class_r == 0)`; else `1` if `gap_r <= f1_mm(arm) + (hysteresis_mm if class_r <= 1)`; else 2 (no enemy gives 2). `want_r = max(fc, geo_r)`. A change to a coarser class waits until `tick - since_r >= min_dwell_ticks`; a finer class applies at once. **Caps:** sort `want == 0` regiments by `(gap, id)` and accumulate `fit`; the first to exceed `f0_cap` and all after it become 1 (strict prefix). Then sort `want <= 1` by `(gap, id)` against `agent_cap` the same way; the rest become 2. On change set `since = tick`.
**Interaction rule.** The shooter's class decides how a shot is made; the target's representation decides how a hit lands. F0 shooter, agent-backed target: SPEC-005 projectile, unchanged. F0 shooter, aggregate target: an F1 shot. F1 shooter: F1 shot. F2 shooter: 6.2. Hits on agents join the one SPEC-005 casualty queue; hits on an aggregate change its counts.

## 5. Hand-overs and conservation
`Aggregate { fit: u32, disabled: Vec<(u64 until, u32 n)> ascending, wounded: u32, killed: u32, rounds: u64, fatigue_sum: u64, fouling_sum: u64, hit_carry_ppm: u32, shot_carry_ppm: u32 }`. `Regiment` gains `status (NotArrived|Present|Departed)`, `class`, `since`.
**Condense** (to class 2): only if no pooled projectile has `unit == regiment`, else the regiment stays F1 and retries next boundary. `fit` = fit roster; each `F_DISABLED` soldier adds to `disabled` by `disabled_until`; each `F_WOUNDED` adds to `wounded`; `rounds`, `fatigue_sum`, `fouling_sum` are sums over all; all are despawned in ascending slot order.
**Materialise** (to class 0 or 1): `n = fit + disabled count`; soldiers spawn on formation slots as `spawn_regiment` does, ascending ids. For a sum `S`, soldier k gets `S / n` plus 1 if `k < S % n` (slot order), so sums are exact. Disabled soldiers take `disabled` entries in ascending `until`. Each takes stream `0x8000_0000 + serial` from a hashed `serial: u32` counter (this amends SPEC-005 section 4, where stream `0x4000_0000 + slot index` is for scenario-start soldiers; recycled slots no longer restart a stream); initial `left` is drawn as there.
**Shared state and streams.** F0 and F1 share all per-soldier state; moving between them changes only how a shot becomes a hit. Every shot reads the same 50 words from the soldier's stream in SPEC-005 order (misfire word first); an F1 shot uses the misfire word and discards 49. A stream position is therefore a function of shots fired, never of class history.
**Ledger** (`Battle::ledger(team)`): `present = agents alive + Σ(fit + disabled + wounded)`; per tick `present_start + arrived == present + killed + departed`. Ammunition: `held + spent + lost == initial + resupplied`, `spent` counting shots and misfires, `lost` the rounds of despawned killed soldiers.

## 6. F1 and F2
**6.1 F1 shot.** Loading, misfire, fouling, fatigue, ammunition: SPEC-005 section 4. A non-misfired shot appends `(ammo, bin, target)` to the regiment's `pending`, bin from the distance to the target anchor. Streams: `STREAM_F1_COUNT = 0x5000_0000 + regiment`, `STREAM_F1_VICTIM = 0x5800_0000 + regiment`. At `tick % bundle_ticks == regiment % bundle_ticks`, for each pending shot in order: `hpp = hits_per_shot_ppm * density_pm / 1000`; `k = hpp / 10^6 + (range_u32(0, 10^6) < hpp % 10^6)`; each hit enters a 128-slot delay ring with `due = tick + ceil(time_of_flight_substeps / 10)`, ordered `(due, shooter, order)`. At `due`: pick rank by `rank_share`, file uniform, from the target's current roster (empty: hit lost); then four victim-stream draws in fixed order: cover (SPEC-005 section 5 rule), region, outcome (damage band from the range table's impact speed at the bin), disabled ticks. The outcome joins the SPEC-005 queue with `seq` from the same counter.
**6.2 F2 exchange.** At `tick % f2_interval_ticks == regiment % f2_interval_ticks`, r targets the nearest present enemy by `(gap, id)` within weapon `extended_mm`. `shot_ppm += fit * f2_interval_ticks * 10^6 / total_load_ticks(weapon, training)`; `s = shot_ppm / 10^6`, remainder carried, capped by `rounds`, `rounds -= s`; effective shots `s * (10^6 - misfire_ppm) / 10^6`. Hits as 6.1 with `hit_carry_ppm` in place of the Bernoulli draw; victim, cover, outcome as 6.1, immediate. On an aggregate, Killed and Wounded move one from `fit` to `killed` or `wounded`; Disabled appends `(tick + n, 1)`, released into `fit` at its tick.
**6.3 Aggregate movement.** Orders and the drill countdown are unchanged. The anchor moves by SPEC-004 section 7 with `A = speed(gait) * terrain.speed_pm * fatigue_speed_pm(fatigue_sum / fit) / 10^6` and no lag halt; mean fatigue follows the SPEC-004 section 4 drain.

## 7. Sector streaming
Sector index `sy * sw + sx`, `sw = ceil(width / sector_mm)` (400 sectors for 10 km). The whole terrain grid stays resident (1.56 MB at 1250 x 1250), so streaming never changes a result. At each boundary a sector is **Hot** if it, or one within `hot_margin_sectors` (Chebyshev), overlaps the box (anchor +/- reach) of a present class 0 or 1 regiment; **Warm** if it overlaps a present F2 regiment; else **Cold**. A sector leaves Hot only while its smoke total is 0. Hot sectors own a `SmokeGrid` tile (zeroed on entry, freed on exit, hashed ascending) and `sector_obstacles[sector]` (ascending obstacle index); `resolve_chord` tests only obstacles of sectors its bounding box overlaps, deduplicated ascending. The agent `SpatialGrid` covers the sector-aligned box of Hot sectors at `grid_cell_mm`, rebuilt only when that box changes; above `max_grid_cells` the cell size doubles until it fits. Agent streaming is the hand-over of section 5, so the store holds at most `agent_cap` soldiers.

## 8. Replay and quick-resolve
Header: `scenario_id`, `seed`, `tick_hz 20`, `fidelity_class = fc` (SPEC-002 unchanged). The first input is `(tick 0, actor 255, seq 0)`, payload `u8 tag 16, u64 scenario_hash` (tags 1 to 5 are SPEC-004 and SPEC-005). `verify` loads `data/scenarios/<id>.toml`, rejects a hash or class mismatch (exit 2), then replays. **Quick-resolve** is `Battle::run(until)`: the same `step` with no rendering, so its hash equals a played run of the same inputs. `hd-sim resolve --scenario ID --seed S [--ticks N] [--out FILE]` prints final hash, ledger, casualties by side, objective holders. Campaign auto-resolve scenarios are authored with `fidelity_class = 2`.

## 9. Public API (exact)
`FidelityClass(u8)`, `FidelityTable::from_toml_str`, `F1Table::from_toml_str`, `Scenario::from_toml_str`, `scenario_hash`, `ScenarioError`, `Aggregate`, `SectorMap::{new, state, hot_window}`, `classify(&FidelityTable, &[ClassInput], fc: u8, f0_cap: u32, agent_cap: u32, tick: u64) -> Vec<FidelityClass>` (`ClassInput { id, team, arm, anchor, reach_mm, fit, class, since }`), `condense`, `materialise`, `Battle::{from_scenario(&Scenario, seed: u64) -> Result<Battle, ScenarioError>, step, run, ledger, objective_holder, hash}`, `fit_f1(&F0Curves, &Tables) -> String`. `Battle::hash` = `battle_hash` plus every field this spec adds (regiment status, class, aggregates, `serial`, sector states, smoke tiles, delay ring, `pending`, trigger cursor), ascending.

## 12. Calibration targets
CT-80 thresholds by arm (casualty continuity at the seam). CT-81 F1 fit. CT-82 caps. CT-83 F1 tolerance. CT-84 F2 tolerance and interval. CT-85 sector size, margin, grid cell. CT-86 bundle window (mean casualty timing shift under 1 s). CT-87 hysteresis and dwell (under 1 class change per regiment per 30 s in `gb_scale_lite`). CT-88 weather rows (hot, high 80s F; storm night of 3 to 4 July, CWV p079; CWV p116).

## 13. Assumptions
A1 map at most 12 km a side. A2 battery strength is guns; crews count only in strength checks. A3 anchor distance less reach suffices for class decisions. A4 player orders address regiments in any class. A5 F2 targets only the nearest enemy. A6 evidence windows (Hood about 4 or 4:30 pm, CWV p069, p081; Pickett step-off about 2 or 3 pm, CWV p069, p083) are data; `at_s` is the chosen value.

## 14. Risks
R1 re-tuning SPEC-005 data moves F1 and F2 (T8-14 forces a refit). R2 binding caps can pit an F0 shooter against an F1 enemy. R3 class-0 quick-resolve runs only at about 1.8 times real time. R4 a wide Hot box makes grid rebuild dear. R5 hand-over pop-in is visible; presentation is outside this spec.
