# SPEC-016: prototype and vendor briefs (M1 renderer, capture, audio, quotes, rights)

> Shared namespaces (input tags and actors, random streams, flags, hash blocks, tick order, CT ids, amendment labels, ticket ids) are owned by [REGISTRY.md](REGISTRY.md); conflicts and their resolutions are in [CONFLICTS.md](CONFLICTS.md).

Scope: work that needs a GPU machine, performers, a recording field or an outside vendor. The only new repository code is `shells/sim-capi` (a C interface to the core), `shells/perf-kit` (integer reference functions for tiers and acoustics, safe Rust, used as test vectors by the prototypes) and small checkers in `tools/` and `qc/perf/`. Prototype renderers live in `prototypes/`, outside the workspace, never shipped, never imported by a crate.
Source key: **CWV pNNN** = research volume, PDF page NNN, with the page's tag. Invented numbers are `placeholder` with a calibration target CT-016-n (section 12). Hypotheses are H16-n (section 10). Test ids use the prefix **T16**.

## 1. Definitions and assumptions
- **RM-R** recommended machine: 8-core, 32 GB, RTX 3070 or RX 6800 class. **RM-M** minimum: 6-core, 16 GB, RTX 2060 or RX 5700 class (CWV p465 9.3 [Estimate/judgement]). Each run records its machine in `qc/perf/machine.toml`.
- **Rendered soldier:** one simulated soldier drawn in tier A (near, skinned), B (mid, baked bone texture), C (far, impostor) or D (horizon density block) (CWV p449 3.2, p450 [Estimate]). **Run:** one scene with one flight, 4200 frames at a fixed 60 Hz camera step, the first 600 discarded. **Snapshot:** an immutable copy of visible core state at a tick.
- Assumptions: a GPU machine exists from week 4 (Plan D4); slab terrain comes from rights-checked public federal elevation data; audio is 48,000 Hz, so a 20 Hz tick is 2400 samples; hosts can call a C ABI; counsel reviews every contract template (nothing here is legal advice). **SPEC-005 amendment A12** (REGISTRY section 9; written first by T-164): `BattleState::drain_events(&mut self, out: &mut Vec<BattleEvent>)`, `BattleEvent { tick: u32, seq: u32, x_cm: i32, y_cm: i32, regiment: u16, weapon: u8, kind: u8 }` (0 shot, 1 misfire, 2 burst, 3 casualty); events are a copy, never hashed.

## 3. M1 renderer prototype brief
**3.1 Build.** Original procedural placeholder soldiers: 5 body shapes, 8 heads, 6 headgear, 6 coats, 8 kits, 4 wear levels (46,080 combinations, six axes) plus phase offset `hash(slot) mod clip_frames` (CWV p449). Twelve procedural clips (march, halt, stand, three load steps, present, fire, kneel, fall, die) on the 6.4 skeleton. A: 15,000 to 40,000 triangles, compute skinned; B: 2,000 to 6,000, bone texture of three texels per matrix, power-of-two width; C: octahedral impostor with normals and depth, dithered cross-fade; D: unit-colour blocks; the dead are static instances (CWV p449, p450 [Estimate]). **Slab:** 3072 m square of the Cemetery Ridge ground, 2 m posting, four blend layers, one mutable crater layer (CT-016-9). **Smoke:** 256 x 256 x 32 grid of 4 m cells, GPU wind advection, quarter or eighth resolution froxels, half resolution soft puffs (CWV p451 3.4 [Estimate]). **Acoustics:** playback only (7.2).
**3.2 Scenes** (snapshots `qc/perf/snap-*.bin` from `f0_large` seed 42, plus one live run through the C interface): S0 empty slab; S1 day assault, 20,000; S2 S1 with full smoke; S3 night skirmish, 6,000, 256 unshadowed muzzle flashes; S4 20,000, rain, wet shading, full smoke; S5 tier stress; S6 gallery, 800 tier-A.
**3.3 Flights** (3600 frames, committed waypoints): F1 ground walk along a regiment front, 1.7 m, 1.5 m/s; F2 low sweep, 10 m, 20 m/s; F3 descent 120 m to 40 m; F4 ridge pan, 25 m, a turn in 60 s; F5 eight stations, a cut every 120 frames. S1 to S4 run F1 to F4; S5 runs F5; S6 runs F1.
**3.4 Protocol.** Three runs per (machine, scene, flight): cold start, pinned driver, no other load, vsync off, upscaler off (an upscaler-on row is reported, never gated). Per frame the harness writes integer microseconds for render-thread, submit, wait-on-simulation, present-to-present and per-pass GPU time, plus draw calls, triangles, tier counts, VRAM and RAM; per tick, simulation and publish time; for audio, callback maximum, underruns, voices. **Percentile:** for `N` sorted samples and `q` in permille (500, 950, 990, 999), `stat = sorted[ceil(q * N / 1000) - 1]`. A verdict uses the median of the three runs and reports the worst. A crash, driver reset or missing file fails the scene.
**3.5 Tiers (integers).** With distance `d_mm`, a soldier enters A at `d < 30,000` and leaves at `>= 33,000`; B likewise at 150,000 and 165,000; C at 600,000 and 660,000; beyond is D (CT-016-1). Caps: A 800, B 6,000 (RM-M 200, 1,500). Over cap, the farthest by `(d_mm, slot)` fall one tier.

## 4. Hosting the core through a C interface (`shells/sim-capi`)
Crate types `cdylib` and `staticlib`; header `include/hd_sim.h`. `unsafe` is allowed in this crate only (ADR 0008, written by T-165; the crate opts out of the workspace `unsafe_code = "forbid"` lint with its own `[lints]` table); every function runs under `catch_unwind` (panic returns `HD_ERR_PANIC`); the three core crates keep `forbid(unsafe_code)`. No float crosses the interface. **Authority:** the renderer reads copies and sends **orders only**; each order passes the SPEC-004 order codec (or the SPEC-007 dispatch codec, tag `0x10`, when the command layer is on, because direct regiment inputs are then refused) and is written to the replay input log, so a host changes nothing a player could not. The host picks when to step; results do not depend on it.
Layouts (little-endian, packed, sizes asserted in C and Rust). `SoldierRec` (32 bytes): `slot u32 @0, generation u32 @4, x_cm i32 @8, y_cm i32 @12, vx_cm_s i16 @16, vy_cm_s i16 @18, heading_turn u16 @20, hp u16 @22, flags u16 @24, regiment u16 @26, team u8 @28, posture u8 @29, activity u8 @30, activity_age_ticks u8 @31` (saturating). `RegimentRec` (20): `id u16, team u8, formation u8, anchor_x_cm i32, anchor_y_cm i32, heading_turn u16, strength u16, can_fire u8, state u8, pad u16`. `EventRec` (20) is `BattleEvent`. Quantisation: `cm = floor(raw * 100 / 2^32)` in `i128`, saturated to `i32`, relative to the scenario origin; `heading_turn = raw >> 16` (1/65536 turn, the unit of the flight files; ticket T-165 owns the function). Records ascend by slot, events by `(tick, seq)`. Snapshot hash: FNV-1a 64 over `tick u64, soldier_count u32, regiment_count u32, event_count u32`, then records. The renderer samples its own heightfield; no height crosses. Snapshots are double-buffered; one stays pinned until released.

**C functions** (all return `int32_t` codes `HD_OK 0, HD_ERR_ARG -1, HD_ERR_STALE -2, HD_ERR_SCENARIO -3, HD_ERR_PANIC -4, HD_ERR_CAPACITY -5` unless stated): `uint32_t hd_abi_version(void)`; `hd_sim_create(const char* scenario, uint64_t seed, uint32_t agents, hd_sim** out)` (scenarios `toy`, `f0_large`); `void hd_sim_destroy(hd_sim*)`; `hd_sim_step(hd_sim*, uint32_t ticks)`; `uint64_t hd_sim_tick(const hd_sim*)`; `uint64_t hd_sim_hash(const hd_sim*)`; `hd_snapshot_acquire(hd_sim*, const hd_snapshot** out)` (drains events into the snapshot); `const hd_soldier_rec* hd_snapshot_soldiers(const hd_snapshot*, uint32_t* count)` and likewise `_regiments`, `_events`; `uint64_t hd_snapshot_hash(const hd_snapshot*)`; `hd_snapshot_release(hd_sim*, const hd_snapshot*)`; `hd_smoke_view(const hd_sim*, hd_smoke_desc* out)` (`cell_mm, width, height, origin_x_cm, origin_y_cm, const uint32_t* density`, valid until the next step); `hd_sim_submit_order(hd_sim*, uint8_t actor, const uint8_t* payload, uint32_t len)`; `hd_sim_write_replay(const hd_sim*, uint8_t* buf, uint32_t cap, uint32_t* len)`.
**`perf-kit` (Rust):** `enum Tier { A, B, C, D }`; `assign_tiers(d_mm: &[u32], slots: &[u32], prev: &[Tier], caps: (u32, u32), out: &mut Vec<Tier>)`; `range_mm(dx: i64, dy: i64, dz: i64) -> u64`; `arrival_sample(tick: u64, range_mm: u64) -> u64`; `cluster_key(regiment: u16, x_cm: i32, y_cm: i32) -> (u16, i32, i32)` (`div_euclid` by 5000); `struct Cluster { key: (u16, i32, i32), shots: u32, range_mm: u64 }`; `select_voices(clusters: &[Cluster], max: usize) -> Vec<usize>` (indices).

## 5. Engine host decision
**Candidates:** host A, a commercial engine with a custom crowd module (recommended, CWV p464 8.7); host B, a custom renderer. Other engines on the CWV p464 matrix are scored on paper unless both fail. B is built only if A misses any H16-1 to H16-3 value by more than 15 percent.
**Hard gates (any failure excludes):** G-a H16-1 to H16-3 and H16-5 pass in S2 and S4 on the production path; G-b T16-01 to T16-06 pass against the host's integration; G-c written licence terms reviewed by counsel; G-d reproducible Windows build from a clean checkout.
**Weighted matrix** (placeholder weights, CT-016-10): measured performance 25; crowd flexibility 20; determinism hosting, lighting, time to slice 10 each; terrain tooling, audio middleware, hiring, console path, long-term control 5 each. Scores 1 to 5; the CWV p464 table (judgement) is the prior, replaced by measurement for the first row. A winner leads by 5 points; else the host with more gate margin wins, then more long-term control.
**Record:** the gate review writes `docs/adr/0009-renderer-host.md` (number reserved in REGISTRY section 17): status, machine records, options, measurement table linking `docs/cycle-reports/CYCLE-M1-renderer.md`, decision, locked thresholds (`locked = true`; later changes only by ADR), consequences, revisit triggers, licences. ADR 0001 allows this revisit. **Failure ladder** (in order, rerun S2 and S4): lower tier caps; smoke grid 128 x 128 x 32; eighth-resolution froxels; 15,000, then 10,000 rendered soldiers. Outcome: PASS, PASS WITH CUTS (cuts written into the plan) or FAIL (change approach before any art is bought, CWV p466 10).

## 6. Animation capture brief
**6.1 Capture list (about 300 clips, CT-016-8; CWV p453 4.1, p454 to p455, p513).** I1 nine-count load and fire; standing, kneeling, prone; styles veteran, recruit, exhausted, frightened, defiant; idle variants (check lock, glance at officer, fumble); misfire; bayonet fix: 45. I2 gaits, halt, turns, slopes, mud, fence, wall, ditch, wading: 50. I3 group drill (lines advancing, files wheeling, ranks closing up; 8 to 40 performers): 18. I4 under fire (advance, hesitate, take cover, look to officer, kneel and prone transitions): 24. I5 stagger, spin, buckle, weapon drop, hand to head, clutch stomach, three falls, crawl, cry: 52. I6 matched pairs, bayonet and clubbed musket: 20. I7 carry, stretcher pair, surgeon: 12. I8 officers, colour-bearer, drummer, bugler, signals: 28. I9 artillery crew numbers 1 to 6, limber, sponge, load, ram, prime, fire: 30. I10 mounted charge, hold, dismount, horse-holder: 21.
**6.2 Performers and consent.** At least 12 named adult performers (pseudonymous in the repository) from experienced reenactor units and trained actors, a military historian present. A clip needs a signed consent row. Agreements state: use in the game and its marketing; **no digital replica** of body or voice and **no machine-learning training** without separate signed consent; pay at or above the guild or union minimum for equivalent work, or a counsel-approved day rate; credit; right to decline any wound, death or surrender action; withdrawal of unreleased takes; deletion of personal data. Faces are out of scope unless tier A shows faces (CWV p453). Safety: replica firearms, no live powder on the stage, a safety officer, a horse welfare plan with a trained handler. Death is depicted soberly (Plan 7.1).
**6.3 Delivery.** Optical 120 Hz, outdoor inertial 100 Hz. Per clip: raw C3D, cleaned FBX at 60 fps, timecoded video, manifest row. Name `^[a-z]{3}_[a-z0-9]+(_[a-z0-9]+){2,6}_v[0-9]{2}$`, first token the category (`inf_fire_cycle_stand_veteran_v01`). A 12-clip pilot (two each from I1, I2, I4, I5, I8, I9) is rendered in the prototype before the order.
**6.4 Skeleton** `data/animation/skeleton_soldier_v1.toml`: right-handed, Y up, +Z forward, metres, A-pose, 64 joints (root, pelvis, three spine, neck, head, two clavicles, arm chains, 30 finger joints, leg chains with ball joints, six twists, five prop sockets); tier B uses a 28-joint subset. Clips store rotations and root translation only; body variants differ by bone length and root motion scales by leg-length ratio; foot contacts ship with each clip. Animation is cosmetic: speed comes from the locomotion table, playback rate stays within 800 to 1250 permille.
**6.5 Acceptance** (automated per clip, CT-016-7): name and manifest complete; 30 to 1800 frames; loops close within 2 degrees mean joint error and 5 percent root-speed jump; foot slide at most 20 mm per contact; marker gaps under 6 frames; joint limits respected; angular speed at most 1200 degrees per second; hand-to-prop distance at most 15 mm while held; no T-pose frames. Set checks: no performer above 25 percent of a category; every Plan reaction present (flinch, take cover, aid wounded, fall, load, fire, march, wheel); human review each cycle.

## 7. Audio brief
**7.1 Recording list (CT-016-8).** 40 variants of single shots for `rifle_58`, `smoothbore_69`, `carbine_52`, `revolver_44` and `napoleon_12` (shot, shell, case, canister) at 10, 50, 200, 500, 1000, 2000 m with close, mid, far microphones; company (20), battalion (100), ragged and rolling fire; misfire, lock, ramrod; bullet passes; shell whistle, burst, ricochet; 24 bugle and drum calls; horses, limbers, boots, gear; ambience (dawn, dusk, town, rain, wind, night woods); reference shots for echo probes at field, treeline, ridge, street. Each take carries distance, load, wind, temperature, humidity (CWV p464 9.1) and a calibration slate.
**7.2 Aggregated fire.** Cluster key `(regiment, floor(x_cm / 5000), floor(y_cm / 5000))`. Per tick the host counts events per cluster; `r` = shots in the last 20 ticks. Band: `r <= 2` single shots (discrete one-shots under 150 m), `<= 15` ragged, `<= 60` rolling, else continuous roar (CWV p456, p514). Same-team clusters over 300 m away in one 200 m cell merge (counts add, centroid integer mean). **Arrival:** `range_mm = isqrt(dx^2 + dy^2 + dz^2)`, `delay_samples = floor(range_mm * 48 / 343)`, `arrival = tick * 2400 + delay_samples` (343 m/s, CWV p457 5.3 [arithmetic]). **Voices:** `gain_q = n * 10^12 / (range_mm + 1000)^2`; take the first 48 clusters by `(gain_q desc, cluster id asc)`; at most 64 voices total, 16 reserved for UI, voice, music (CT-016-5). Behind a ridge (heightfield ray test) the 4 kHz band falls at least 12 dB (CT-016-5).
**7.3 Voice.** Drill-manual commands (battalion 40, company 40, sergeants 30, artillery 24, cavalry 16), wounded cries, rally, and groups of 6, 12, 40 voices for Union cheers and the Confederate yell, from at least 24 layered performers (CWV p514). Scripts reviewed by the historian and a dialect coach; slurs excluded unless counsel and the narrative framing allow. Consent as 6.2; no synthetic voices of real people.
**7.4 Music.** Public-domain tunes arranged anew by contracted musicians; an original score by a human composer; at least four adaptive stems (bed, pulse, melody, intensity) with tempo, key and loop points in metadata; notation and source edition delivered.
**7.5 Loudness and delivery.** BS.1770 measurement (method from memory). Targets (CT-016-6): scene mix -20 LUFS integrated plus or minus 2 LU in every output mode; true peak at most -1.0 dBTP; no clipping; noise floor at most -60 dBFS; voice lines -23 LUFS; music cues -20. Effects keep calibrated levels, peak at most -1 dBFS. 48 kHz, 24-bit BWF WAV; mono close and mid, AmbiX first-order far beds; `snd_<category>_<source>_<distance>_<variant>_<nn>.wav`, one manifest row each.

## 11. Acceptance tests (T16-01 to T16-13 run in CI; T16-14 to T16-18 on the GPU machine at M1)
- **T16-01 layout:** `hd_abi_version() == 1`; a C program built with the system `cc` asserts sizes (32, 20, 20) and every section 4 offset; the Rust test asserts the same.
- **T16-02 determinism:** scenario `toy`, 20,000 agents, seed 42, 600 ticks gives the hash of `hd-sim hash --agents 20000 --ticks 600 --seed 42` (CYCLE-00: dd9a31d011f3ecd8); stepping 1 x 600, 60 x 10, 600 x 1 agree.
- **T16-03 read-only:** a pinned snapshot is unchanged after 10 ticks; a run taking a snapshot every tick ends with the hash of a run taking none; the header exposes record types only through `const` pointers.
- **T16-04 content:** for `toy` seed 1, 100 agents, 100 ticks, `x_cm`, `y_cm` are within 1 cm of the `f64` position times 100 (test code only); slots ascend; `hp`, `team` equal the store.
- **T16-05 hash and events:** a C host recomputes FNV-1a 64 over snapshot bytes and matches; events ordered by `(tick, seq)`; draining twice returns each event once.
- **T16-06 orders and errors:** orders sent by `hd_sim_submit_order` appear in the replay from `hd_sim_write_replay`, which `hd-sim verify` accepts; 1,000 random invalid argument sets (null, stale, oversized) return error codes with no panic or abort.
- **T16-07 percentiles:** `qc/perf/summarise.py` on 1 to 1000 gives p50 500, p95 950, p99 990, p99.9 999, max 1000.
- **T16-08 arrival** (`perf-kit`): 343,000 mm gives 48,000 samples; 1,000,000 mm gives 139,941; 0 gives 0; tick 3 adds 7,200.
- **T16-09 tiers:** a soldier at 29,999 mm is A, at 31,000 stays A, at 33,000 is B, at 31,000 stays B, at 29,999 is A; 1,000 soldiers within 30 m give exactly 800 A (nearest by `(d_mm, slot)`) and 200 B.
- **T16-10 voices:** `select_voices` for 200 random clusters the chosen 48 equal a brute-force sort; ties go to the lower id.
- **T16-11 clip checker:** `tools/check_clips.py` accepts 10 and rejects 10 names; on a fixture manifest it fails on missing consent, a performer above 25 percent of a category, and counts differing from 6.1.
- **T16-12 rights checker:** `tools/check_rights.py` fails fixtures with an unknown licence, `ai_tool` set without `human_authored`, a voice row without consent, `replica_allowed = true` without a counsel reference.
- **T16-13 skeleton:** 64 unique joints, parent index below child index, a 28-joint tier-B subset inside them.
- **T16-14 protocol:** every S0 to S6 run has its files; `summarise.py` evaluates H16-1 to H16-6 and H16-11 per row. **T16-15** H16-7. **T16-16** H16-8, H16-10. **T16-17** H16-9 with T16-08 and T16-10 on live events. **T16-18** the ADR exists, its machine records match `machine.toml`, threshold rows are locked. Numbers are recorded once in the cycle report.
